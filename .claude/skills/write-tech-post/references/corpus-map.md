# 코퍼스 인덱스

writer/reviewer 는 새 포스트를 쓰기 전에, 아래에서 **주제가 가장 가까운 2~3편을**
`apps/web/content/posts/ko/` 에서 **전문 정독**한다. 화법·전개·장치의 기준선은 항상 실제 코퍼스다.

| 파일 (`ko/`)                          | category | 유형               | 전개 특징                                                                                                  | 참고 모델로 삼을 상황                                                       |
| ------------------------------------- | -------- | ------------------ | ---------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| `custom-website-journey-001.mdx`      | tech     | 계기·방향 서술형   | 시간 배경으로 시작 → "왜 지금" → 선택지 고민(직접 구현 vs 전부 위임) → 결정 배경 → 기술 스택 개괄 → 마치며 | 프로젝트/도구 도입의 **동기와 방향**을 설명하는 글. 코드보다 서사 비중이 큼 |
| `custom-website-journey-002.mdx`      | tech     | 구현 상세형        | 도구 소개(번호 `###`) → 기능별 구현(`##`) → 코드 스니펫 + "이 값이 핵심입니다" 해설 → 마치며               | 특정 기능/시스템을 **어떻게 만들었는지** 코드와 함께 풀어내는 글의 표준형   |
| `custom-website-journey-003.mdx`      | tech     | 구현 상세 + 회고형 | 기능별 구현 → 배포 → **마치며에서 수치·비용·뒤늦게 깨달은 인사이트** 공유                                  | 프로젝트/작업을 **마무리하며 회고**하는 글. 정량 데이터와 교훈을 담을 때    |
| `cloudflare-domain-vercel.mdx`        | tech     | 비교·의사결정형    | 후보 나열 → **비교표 + 표 아래 각주(`\*`)로 항목별 해설** → "결론: X 선택" + 근거 목록 → 실행 과정         | 여러 선택지를 **비교해 하나를 고른** 과정을 설명하는 글. 표가 중심축        |
| `harness-engineering-with-claude.mdx` | tech     | 책 리뷰 + 적용형   | 실무 고민 → 책 관점 → 개념별 `##`(인용·표) → 적용해보기 → 마치며                                           | 책 리뷰는 `write-book-review` 스킬 사용. 여기서는 개념 정리 화법 참고용     |
| `book-review-growing-together.mdx`    | life     | 독후감·에세이형    | 책 인용 → 개인 경험 대입 → 성장에 대한 사유                                                                | (life 카테고리 참고용. 책 리뷰는 `write-book-review` 스킬 사용)             |

## 유형 선택 가이드

- 입력이 **"이 기능/시스템을 이렇게 구현했다"** → `002` 를 주 모델로. 코드 스니펫마다 "이 한 줄/이 값이 핵심입니다" 식 해설을 붙인다.
- 입력이 **"A, B, C 중 무엇을 고를까 고민했다"** → `cloudflare` 를 주 모델로. 비교표를 만들고 표 아래에서 `\*` 각주로 항목을 하나씩 푼다.
- 입력이 **"이런 걸 왜 시작했고 어떻게 접근했다"** → `001` 을 주 모델로. 시간 배경으로 문을 연다.
- 입력이 **프로젝트를 끝낸 회고** → `003` 을 주 모델로. 마치며에 기간/수치/뒤늦은 깨달음을 넣는다.
- 대부분의 tech 포스트는 위 유형이 섞인다. 주 모델 1편 + 보조 모델 1~2편을 정독하고 혼합한다.

## 이미지 참조 규약

코퍼스는 `![설명](/images/posts/<series-or-slug>/<name>.png)` 형식으로 이미지를 넣는다.
**이 스킬은 이미지를 생성하지 않는다.** 스크린샷이 꼭 필요한 자리에는
`{/* TODO: 스크린샷 — <무엇을 담을지> */}` MDX 주석을 남기고, publish 전에 사용자에게 알린다.
(주석이 아닌 깨진 `![](...)` 링크를 본문에 남기지 말 것.)
