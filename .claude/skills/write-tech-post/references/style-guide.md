# hijero.me tech 포스트 스타일 가이드

> **이 파일은 매 세션의 품질·화법을 고정하는 단일 진실 소스다.**
> writer 와 style-reviewer 는 매번 이 파일을 정독한 뒤 작업한다.
> 사용자에게서 같은 지적이 2회 이상 나오면, 그 교정을 이 파일에 규칙으로 추가한다
> (일회성 피드백은 `.claude/agent-memory/tech-post-writer/MEMORY.md` 로).
> 규칙과 실제 코퍼스가 어긋나면 **코퍼스가 우선**이다 — `corpus-map.md` 참고.

## 1. 인칭과 어조

- 1인칭 단수: "저는", "제가", "제 생각에는". 필자를 "우리"로 부르지 않는다.
- 독자에게 존댓말(합쇼체): 문장은 기본적으로 "~습니다 / ~했습니다 / ~입니다" 로 끝난다.
- 연결·완충 어미를 섞어 딱딱함을 던다: "~했는데요", "~습니다만", "~더군요", "~네요", "~죠".
  - 예: "관리해야 할 동기부여가 덜했다 보니 소홀해지더군요."
  - 예: "별도 API 엔드포인트가 필요 없으니 서버 비용도 없고, 응답도 빠르죠."
- 과하지 않게: 한 문단에 완충 어미 1개 정도. 문단 대부분은 정갈한 "~습니다".
- 독자에게 질문을 던지는 문장을 가끔 사용한다: "~ 알고 계셨나요?", "~ 아닐까 하는 생각에서".

## 2. 문단과 문장

- 한 문단 = 2~4문장, 한 아이디어. 긴 문단은 쪼갠다.
- 문단 사이 빈 줄 1개. 리스트 앞뒤로도 빈 줄.
- 문장은 중간 길이. 한 문장에 쉼표로 3개 이상 절을 매달지 않는다.
- 불릿은 **정보를 병렬 나열할 때만**. 사고의 흐름·이유·전환은 문장(서사)으로 쓴다.
  불릿이 연속 10개를 넘어가면 서술로 되돌린다.

## 3. 전개 골격

대부분의 tech 포스트는 아래 5단계를 따른다. 순서를 지키되, 글 성격에 따라 ②~④는 반복·생략될 수 있다.

1. **계기 / 맥락** — 시간이나 상황 배경으로 문을 연다.
   "때는 바야흐로 2021년 7월…", "본 hijero.me 웹사이트를 구현하고…", "지난 1편에서는 …소개해봤는데요."
   연작이면 첫 문단에서 이전 편을 링크하고 이번 편 범위를 한 문장으로 예고한다.
2. **고민한 선택지와 트레이드오프** — 보통 후보 2~3개를 놓고 각각의 장단점을 솔직하게 편다.
   "먼저 … 방식입니다. … 반대로 … 방식도 선뜻 내키지 않았습니다."
3. **결정과 배경** — "결론적으로 / 결국 …를 채택했습니다" 뒤에 근거를 목록이나 짧은 문단으로.
   숫자·제약·비용 같은 구체 근거를 댄다.
4. **구현 디테일** — `##` 로 큰 덩어리(프론트/백/인프라, 기능 A/B/C)를 나누고, 필요하면 `###` 로 세분.
   기술명은 **볼드**로 리드하고 이어서 설명: "**Next.js App Router v16+**: 블로그 포스트는 …".
   코드 스니펫에는 반드시 "이 값이 핵심입니다" 류의 해설을 붙인다(§5).
5. **마치며** — `## 마치며` / `## 글을 마무리하며` / `## 글을 맺으며`.
   소요 기간·시간·비용 같은 수치, 구현하며 배운 점, 뒤늦게 깨달은 인사이트, 다음 글 예고, 감사 인사.

## 4. 서식 장치 (코퍼스에서 관찰된 것만)

- **비교표**: 선택지 비교는 마크다운 표로. 열은 후보, 행은 평가 항목.
  표가 복잡하면 항목 이름 옆에 `\*` 를 달고, 표 아래에서 `**항목명**은 …` 형식으로 하나씩 푼다.
  (`cloudflare-domain-vercel.mdx` 참고)
- **인용 블록 `>`**: 목표 선언, 외부 답변 인용, 책 구절에 사용. 여러 줄은 `<br/><br/>` 로 줄바꿈.
- **강조**: 핵심 개념은 **볼드**. 문장 안에서 특정 구절을 짚을 때는 `<u>밑줄</u>` 도 씀.
- **인라인 코드**: 식별자·파일명·설정값·짧은 수식은 백틱. 예: `rootMargin: '-20% 0% -70% 0%'`, `SHA-256(IP + User-Agent + Accept-Language)`.
- **코드 블록**: 언어 태그를 붙인다(`ts, `tsx, `sql, `yaml). 파일에서 따온 것이면
  첫 줄에 `// apps/web/lib/notion/projects.ts` 처럼 경로 주석. 20줄 넘으면 핵심만 발췌하고 `… 중략 …`.
- **링크**: 처음 등장하는 도구·서비스·이전 편은 인라인 링크. 배포 URL은 `https://hijero.me/ko/tech/<slug>`.
- **이미지**: 이 스킬은 생성하지 않는다. 필요한 자리에 `{/* TODO: 스크린샷 — 설명 */}` 주석만 남긴다.
- **수평선 `---`**: 큰 단락 전환(도구 소개 → 구현, 본문 → 후기)에서 가끔.
- **이모지**: 쓰지 않는다.

## 5. 코드 스니펫 원칙

- 스니펫은 **주장을 뒷받침할 때만** 넣는다. "코드를 붙였으니 알아서 보세요" 금지.
- 모든 스니펫 뒤에 1~3문장 해설. 특히 **"이 한 줄이 핵심입니다 / 이 값이 핵심입니다"** 로
  독자가 봐야 할 지점을 짚는다. (예: `passive: true` 가 왜 중요한지, `-mt-12` 가 무슨 효과인지)
- 개념 설명이 코드보다 우선. 코드 없이 문장으로 충분하면 코드를 넣지 않는다.
- 입력 재료에 없는 코드를 지어내지 않는다. 불확실하면 스니펫 대신 산문으로 개념만 전달한다.

## 6. 메타데이터 규칙

- **title**:
  - 연작형: `"<시리즈명> N. <부제>"` (예: "나만의 웹사이트 구축기 2. AI 협업 도구, …")
  - 실용형: `"<대상>로 <행위>하기"` (예: "Cloudflare로 도메인 구매하고 Vercel에 연동하기")
  - 콜론·따옴표가 들어가면 전체를 작은따옴표로 감싼다.
- **description**: 1~2문장. 무엇을 다루는지 나열 + "~담았습니다 / 공유합니다 / 정리했습니다".
- **tags**: 3~5개. 고유명사 기술명은 원표기(`Next.js`, `Supabase`, `Claude Code`), 개념어는 한글(`애자일`, `성장`).
- **publishedAt**: 오늘 날짜(작성일)를 `'YYYY-MM-DD'` 로. 작은따옴표 필수.
- **category**: 항상 `tech`.
- **slug**: 영문 kebab-case. 파일명과 일치.

## 7. 금지 목록

- 마케팅·홍보체("혁신적인", "놀랍게도", "여러분도 지금 바로").
- 이모지, 과도한 느낌표.
- AI 상투구의 반복: "결론적으로 말하자면", "종합해보면", "앞서 언급했듯이" 를 문단마다 반복하지 않는다.
- 불릿 남용 — 사고 흐름을 개조식으로만 나열하는 것.
- 근거 없는 단정("이게 최선입니다"). §8 의 태도를 따른다.
- 입력 재료에 없는 사실·수치·코드·인용의 창작.
- 독자를 가르치려는 훈계조("~해야 합니다"의 남발). 필자 경험으로 말한다("~해보니 …했습니다").

## 8. 사고 방식 / 화자의 목소리

- 주관적인 의견과 판단은 다음과 같이 말한다: "~라 판단했습니다", "~같았습니다", "~인 듯합니다".
- 확실한 근거가 있는 사실은 단정적으로 표현한다.
- 타인의 말을 인용할 때는 다음과 같이 말한다: "~라고 말하고 있습니다.", "~라고 합니다."
- 망설임과 트레이드오프를 숨기지 않는다: "선뜻 내키지 않았습니다", "고민이 좀 됐습니다".
- 실용주의: "필요한 기능을 리스트업 해보니 생각이 바뀌었습니다", "지금 규모에서는 오버엔지니어링".
- 배움을 드러낸다: "이번 기회에 알게 됐네요", "뒤늦게 깨닫게 된 게 있었습니다".
- 겸손하되 근거는 댄다: 자랑 대신 "왜 그렇게 했는지"를 설명한다.
- 욕설, 자아도취적 발언, 대외적으로 불분명한 소스의 참조 인용 등은 절대 하지 않는다.

## 9. 길이와 밀도

- 본문 대략 1,500~2,800 단어(공백 포함 한글 기준 약 3,000~6,000자).
- `reading-time` 패키지 기준 예상 읽기 시간 약 6~14분 (한국어는 실제보다 2~2.5배 길게 추정됨 — 정상).
- `##` 헤딩 3개 이상, 보통 4~7개. 마지막은 항상 "마치며" 계열.
- 너무 짧으면(스크롤 2~3번) 재료가 부족한 것 — 사용자에게 추가 입력을 요청한다.
